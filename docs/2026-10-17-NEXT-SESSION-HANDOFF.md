### 2.2 邀请码

用户询问是否存在邀请码。最新公开OpenAPI的LoginRequest字段为username、password、captcha、rememberMe，没有邀请码字段。当前不添加邀请码输入或邀请码门槛；后续只有服务端明确契约变化才重新评估。

### 2.3 忘记密码

用户要求原生接入找回密码，不跳转。当前公开OpenAPI未列出找回密码接口，因此尚未接入，也不编造URL或请求参数。

下一步核对：账号识别方式、图片/短信/邮件验证码、验证码会话关联、校验有效期、限流、重置提交格式、密码规则、重置后旧会话撤销语义。确认实际接口后做应用内分步流程，日志不记录密码或验证码。未具备契约时明确说明功能状态，不伪装成已接通。

2026-10-21 核对：`LoginPage.ets` 的 `handleForgot`（L67-70）只清空本地密码与验证码字段并切换 `showForgot`，不发起任何网络请求；`SchoolServicePage.ets` 的 `forgotMode`（L30/L43/L46）仅用于标题文案。当前实现是引导说明「密码由学校统一身份认证平台管理，请联系学校信息服务部门重置」，与上面「未具备契约时明确说明功能状态」一致，属正确终局，不是待补项。日后公开 OpenAPI 若出现找回密码接口，再按上述核对项实施。

## 7. 原生小艺任务接入

用户明确希望一句话创建学习任务，例如“明晚八点提醒我复习数据库”。目标链路：小艺理解请求 → 应用任务意图接收标题和时间 → 有歧义时原生确认 → 持久化任务 → 系统登记提醒 → 卡片同步。

本机SDK存在InsightIntent相关接口，但尚未完成官方接入资格、标准意图类型、发布配置、调用参数及API24设备能力核实。存在接口声明不代表可以随意内嵌小艺、注册任意语句或直接调用系统待办。

两条边界：

- 外部小艺调用应用任务能力，与应用内嵌小艺对话框是不同能力；优先研究前者。
- 时间解析与准时送达是两件事；小艺接入不修复1700002，提醒仍需独立系统登记。

若平台提供对应意图：实现创建任务、可核实的执行结果、重复请求幂等、防止静默改动其他账号数据；敏感或有歧义的参数用户确认。若平台尚不提供所需能力，说明具体缺口，保留原生手动创建；不引入第三方模型冒充小艺。生成图中“小艺确认浮层”仅概念，不是可调用系统UI的证据。

### 7.1 核实结果（2026-10-21）

平台能力本身不是门槛：意图执行器 `@since 11`，装饰器全套 `@since 20`，`insightIntentProvider` `@since 23`，都在 API 23 最低线内。`insightIntentProvider` 恰好卡线，无下探余量，不能当余量用。

真正的缺口在标准意图清单。本机 SDK `ets-loader/insight_intents/schema/` 下共 101 个标准意图，按待办/提醒/日程/任务/备忘/日历检索只命中 `StartMeeting`、`ViewSchoolCalendar`、`ViewStockIssuedCalendar`，**没有任何“创建待办”或“创建提醒”意图**。教育域只有 `ViewSchoolTimetable`（查看课程表）与 `ViewSchoolCalendar`（查看校历），都是查看型。

所以本节开头那个场景——“明晚八点提醒我复习数据库”一句话建任务——**标准意图无承载**。不是实现没做，是平台清单里没有这一项。待办能力的价值不应依赖小艺能否唤起。

可做且收益确定的只有两条：

- `ViewSchoolTimetable`：`domain: EducationDomain`，`parameters` 为空对象，结果 `{code, result}` 由应用填充。应用有真实课表数据，语义吻合，落地成本低。
- `JumpFunctionPage`：接受 `pageId: string`，能让小艺跳到待办页，但只到“打开页面”，用户仍需手动输入。

自定义意图能否被小艺主动识别、以什么话术触发，SDK 声明文件无任何说明，未确认，不作承诺。`module.json5` 目前无任何 intent 配置，接入未开始。

完整证据见 `docs/2026-10-21-xiaoyi-intent-contract.md`。
