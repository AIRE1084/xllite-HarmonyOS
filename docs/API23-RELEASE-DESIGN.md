## 顺序与边界

1. 最低 API23，继续使用已有 API26 编译 SDK；API23 使用兼容原生背景材质，高版本开启经过能力检测的 ImmersiveMaterial。同步完善减少动效、触控反馈、标签切换和生命周期隔离。
2. 原生账号密码与验证交互，不向用户展示学校网页跳转。以 XLLite 实际文档和客户端源码核实认证；不假设学校各域名 token 通用。凭据不进日志或 Git。
3. 依文档实现真实接口与结构校验，先无凭据连通性和契约测试，认证后由用户在应用内手动登录再测试。支付不作为只读接口测试附带执行。
4. “新理之山”图标：山脊与书页形成独立几何标记，延续靛蓝/冰蓝与克制玻璃高光；1024方形PNG和矢量母版，同步应用、启动和商店资源。学校官方身份采用用户确认的定位，不从旧第三方项目的定位推导发布资质。

## 已观察到的协议差异

本机 SDK 的 @ohos.arkui.uiMaterial 将模块、ImmersiveMaterial、光感交互全部标为 since 26.0.0。因此 API23 不直接调用该能力，需检测和兼容实现。

XLLite main/docs/api.md（2026-10-16 获取）记录版本0.1.0，Base URL为旧HTTP地址，POST /api/v1/run携带username/password/feature；仅8个业务，无通用token认证契约。项目当前XlliteGateway声称的13业务和auth路径需独立核实，不视为已证实实现。真实凭据仅在确认的加密通道与协议中使用。

补充在线证据：2026-10-16 `https://xllite.sayqz.com/health` 返回200及ok；公开 `/api/v1/openapi.json` 明确提供auth/login、session、refresh、logout和Bearer业务协议。此实时契约优先于旧docs/api.md；原始公开JSON保留在.wolf/project-audit-20261016/xllite-openapi.json。未向旧HTTP地址发送凭据。
